## 四、怎么打包（M11 的完整流程）

```bash
# 1. 先打 Worker 单文件可执行程序（约 125MB，含 Node 运行时）
node scripts/build-worker.mjs

# 2. 再打桌面端安装包（会把 dist-worker/ 整个作为 resources 打进去）
cd apps/desktop && pnpm exec tauri build --bundles deb
```

产物在 `apps/desktop/src-tauri/target/release/bundle/deb/`。

**Windows 包必须在 Windows 上构建** —— `better-sqlite3` 是按目标平台编译的原生扩展。打 `v*` 标签会触发 `.github/workflows/release.yml`，在 windows-latest 与 ubuntu-22.04 两个 runner 上出包。

### 打包时最容易踩的四个坑（都已修，别改回去）

1. **SEA 只能跑 CJS**：没有顶层 await，没有 `import.meta`。Worker 入口因此拆成 `bootstrap.ts`（导出函数）+ `main.ts`（CJS 安全的调用方）。
2. **原生模块不能 external**：SEA 里的 `require` 只认内置模块。走 esbuild `--alias` 指到运行时解析的垫片（`scripts/sea-shims/`），由 `requireExternal` 按可执行文件位置查找。
3. **依赖要按 package.json 递归拷**：pnpm 是隔离式布局，`cp -rL node_modules/better-sqlite3` 会漏掉并列在 `.pnpm` 下的 `bindings`、`node-addon-api`。`copyModuleClosure` 负责展开，缺任何一个就构建期失败。
4. **Worker 路径必须按资源目录解析**：装完之后从快捷方式启动，工作目录是任意的，`./autojob-worker` 一定找不到。用 `app.path().resource_dir()`。

## 六、重要约定（改代码前必读）

完整版见 `CLAUDE.md`，这里只列最容易踩的：

- **`materials/` 是隐私目录**，已 gitignore，**永远不要提交**
- **测试代码禁止出现真实手机号/身份证/邮箱**，一律用虚构数据
- 所有日志必须走 `@autojob/core` 的 `createLogger`（自带 PII 脱敏）；ESLint 已禁止业务代码直接 `console.*`
- 浏览器全局（`document`/`window`）只允许出现在提取脚本里（见 `eslint.config.js` 的白名单）
- 提交前跑 `pnpm privacy:check`，它已并入 `pnpm check`
- 每轮开发按六步走：查仓库 → 说明改哪些文件 → 实现**一个**小功能 → 跑 `pnpm check` → 修失败 → 总结
- **禁止为了让测试通过而删测试**
- **桌面端不做「一键批量投递」**（PRD §3.7）。这不是没做完，是有意不做

## 七、架构速览（避免重新读一遍代码）

```
Tauri 外壳（Rust）
  ↓  拉起子进程，读 stdout 握手 AUTOJOB_WORKER_READY <port> <token>
本地 Worker（Node，127.0.0.1 + 一次性令牌）
  ↓  HTTP
React 界面（只读看板，不发起投递）

—— 投递主链路（CLI 驱动）——
页面 DOM
  ↓  EXTRACT_FIELDS_SCRIPT（浏览器侧，form-schema/raw-field.ts）
RawField[]
  ↓  classifyForm（form-schema/classifier.ts）
FormField[]  ← 带 semanticType + confidence
  ↓  mapForm（form-mapper/mapper.ts）
FormPlan     ← 每个字段 filled / skipped / ask_user + warnings
  ↓  fillForm（browser/filler.ts）
真实填入浏览器 → validateForm → 截图 → SQLite 落库
  ↓  buildDiff（application-diff）
Application Diff → 用户核对 → **提交前停止**
  ↓  用户确认后 submit
verifySubmission（三重证据）→ 写 application_events
```

**三道闸**（记录要进某字段必须全过）：

1. Profile 的 `shouldNotMapTo`（M1 定的，规则不可解除）
2. MappingRule 的 `blockedCandidateTypes`（各级规则并集）
3. 字段置信度 ≥ 0.7

## 八、跨会话恢复的注意事项

- **代码全在 git 里**（分支 `main`，无远程）。M0–M4 是一次性初始提交，此后每个里程碑单独提交
- **`pnpm privacy:check` 是提交前的最后一道关**。它会从 `materials/profile.local.json` 读出你的真实信息，在所有 git 跟踪文件里搜一遍。没有那份文件时退化为通用模式扫描
- **`materials/` 不在 git 里**，它在磁盘上。如果要换机器或重装系统，**记得单独备份这个目录**（简历、证书、论文、专利、投递记录都在里面）
- `node_modules/`、Playwright 浏览器、`dist-worker/`、`.worker-build/`、Rust 的 `target/` 都不在 git 里。重装后跑一次 `pnpm install` + `pnpm exec playwright install chromium` 即可
- 桌面端需要 Rust 工具链。国内网络下官方源握手容易失败，用清华镜像：
  `RUSTUP_DIST_SERVER=https://mirrors.tuna.tsinghua.edu.cn/rustup`，crates 用 `rsproxy.cn`
- Linux 上还需要 `libwebkit2gtk-4.1-dev` 等系统依赖，清单见 `.github/workflows/release.yml`
- 详细的每轮记录在 `docs/03-进展/PROGRESS.md`，最新的在最上面
