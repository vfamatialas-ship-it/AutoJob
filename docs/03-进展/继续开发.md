## 四、M8 要做什么（下次直接从这里开始）

M8 = 第一个真实 ATS Adapter。**目标已定：飞书招聘**（小鹏、德赛西威都用它）。

选型依据是 M7 的实地探测结论，不是推断 —— 详见 `docs/05-调研/ATS初步识别.md`：
两家飞书站的脚本来源**一字不差**，说明是标准化 SaaS，一个 Adapter 能覆盖多家。

### 4.1 第一步不是写 Adapter

**先搞清楚飞书招聘的岗位数据从哪来。** M7 探测发现：
`*.jobs.feishu.cn` 的首屏与 `/campus/position` 路由都只有 5–6 个导航链接、
正文 42–52 字，**没有任何职位内容**。岗位由 SPA 异步加载。

所以第一步是观察 XHR 请求，找到它的内部 API 或正确的路由参数。
这一步做完，后面的 Adapter 实现就水到渠成。

### 4.2 任务清单

1. **探查数据来源**：headless 打开页面，监听 network，找出岗位数据的请求
2. **抓 DOM fixture** 存入 `tests/fixtures/dom/`，让 Adapter 测试**不依赖线上站点**（PRD §58）
3. **`packages/ats-detector`**：`*.jobs.feishu.cn` + 飞书 CDN 脚本来源双信号
4. **`packages/adapters/feishu`**：实现 `ATSAdapter` 接口的 14 个方法（PRD §23），
   业务层不接触 DOM
5. **页面变化恢复**（PRD §72）：主 selector 失败 → 备用 selector → Generic 兜底 →
   生成「Adapter Update Candidate」交人工确认，不直接改正式规则

### 4.3 M8 的验收标准

- [ ] 全部 Adapter 测试跑在 fixture 上，CI 中无网络依赖
- [ ] ATS Detector 对飞书招聘的识别 confidence > 0.9
- [ ] 能在真实站点上读出岗位列表（**只读**）
- [ ] 在真实站点上手动验证一次填写（**不提交**）

## 六、重要约定（改代码前必读）

完整版见 `CLAUDE.md`，这里只列最容易踩的：

- **`materials/` 是隐私目录**，已 gitignore，**永远不要提交**
- **测试代码禁止出现真实手机号/身份证/邮箱**，一律用虚构数据
- 所有日志必须走 `@autojob/core` 的 `createLogger`（自带 PII 脱敏）；ESLint 已禁止业务代码直接 `console.*`
- 浏览器全局（`document`/`window`）只允许出现在 `form-schema/src/raw-field.ts` 与 `browser/src/page-scripts.ts`
- 提交前跑 `pnpm privacy:check`，它已并入 `pnpm check`
- 每轮开发按六步走：查仓库 → 说明改哪些文件 → 实现**一个**小功能 → 跑 `pnpm check` → 修失败 → 总结
- **禁止为了让测试通过而删测试**

## 七、架构速览（避免重新读一遍代码）

```
页面 DOM
  ↓  EXTRACT_FIELDS_SCRIPT（浏览器侧，form-schema/raw-field.ts）
RawField[]
  ↓  classifyForm（form-schema/classifier.ts）
FormField[]  ← 带 semanticType + confidence
  ↓  mapForm（form-mapper/mapper.ts）
FormPlan     ← 每个字段 filled / skipped / ask_user + warnings
  ↓  fillForm（browser/filler.ts）
真实填入浏览器 → validateForm → 截图 → SQLite 落库 → **提交前停止**
  ↓  buildDiff（application-diff）
Application Diff → 用户核对 → **提交前停止**
```

**三道闸**（记录要进某字段必须全过）：

1. Profile 的 `shouldNotMapTo`（M1 定的，规则不可解除）
2. MappingRule 的 `blockedCandidateTypes`（各级规则并集）
3. 字段置信度 ≥ 0.7

**关键包**：

| 包                           | 职责                                   |
| ---------------------------- | -------------------------------------- |
| `@autojob/core`              | Result、错误码、PII 脱敏、日志、Run ID |
| `@autojob/candidate-profile` | 数据模型 + 查询层（红线的唯一执行点）  |
| `@autojob/form-schema`       | DOM 提取、label 归因、语义分类         |
| `@autojob/form-mapper`       | 规则引擎、取值映射、warning 生成       |
| `@autojob/browser`           | Playwright 会话、状态机、填写、校验    |
| `@autojob/database`          | SQLite 投递记录与事件时间线            |
| `@autojob/content-adapter`   | 抽取式压缩 + Canonical Facts 校验器    |
| `@autojob/application-diff`  | 提交前的转换说明与溯源展示             |
| `@autojob/job-discovery`     | 通用岗位列表解析（重复结构识别）       |
| `@autojob/job-matcher`       | Hard Filter + 确定性打分               |

## 八、跨会话恢复的注意事项

- **代码全在 git 里**（分支 `main`，无远程）。M0–M4 是一次性初始提交，此后每个里程碑单独提交
- **`pnpm privacy:check` 是提交前的最后一道关**。它会从 `materials/profile.local.json` 读出你的真实信息，在所有 git 跟踪文件里搜一遍。没有那份文件时退化为通用模式扫描
- **`materials/` 不在 git 里**，它在磁盘上。如果要换机器或重装系统，**记得单独备份这个目录**（简历、证书、论文、专利、投递记录都在里面）
- `node_modules/` 和 Playwright 浏览器不在 git 里，重装后跑一次 `pnpm install` + `pnpm exec playwright install chromium` 即可
- 详细的每轮记录在 `docs/03-进展/PROGRESS.md`，最新的在最上面
